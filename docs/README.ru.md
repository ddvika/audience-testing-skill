# Audience

**Дайте вашему продукту аудиторию из AI-агентов.**

Десятки и сотни агентов пробуют ваш продукт в роли разных пользователей. Audience — открытый скилл, который задаёт им разные персоны, проводит по реальным сценариям в браузере и собирает понятный отчёт: где они застряли, что получилось и что улучшить.

Вы задаёте сайт, исследовательский вопрос и бюджет. Можно начать с небольшой группы или запросить до **1 000 персон** с выбранными моделями OpenRouter. Сколько сценариев завершится, зависит от бюджета, времени и возможностей браузера. Это моделирование пользовательского опыта; агенты не заменяют выборку реальных клиентов.

## Как поставить задачу

> Используй Audience: протестируй `https://your-product.example`.
> Проверь, понимают ли новые пользователи, как получить первый полезный результат.
> Сам выбери аудиторию и модели. Бюджет OpenRouter — до $2, время — до 30 минут.

Можно задать состав аудитории, число агентов и конкретные модели самостоятельно. Ассистенту нужны доступный браузер, Python и сеть: сам скилл этих возможностей не добавляет.

## Что будет в результате

- **Дизайн эксперимента:** кто тестировал, почему выбраны эти группы, что планировали проверить и что действительно проверили.
- **Подтверждения:** действия в браузере, видимые ответы и ссылки на события. Сохранённые переписки доступны в отдельном приложении с выгрузкой TXT и JSON.
- **Приоритеты для продакта:** до трёх подтверждённых проблем, конкретные изменения и критерий повторной проверки.
- **Измерения:** выполнение задач, этапы клиентского пути, понятность интерфейса и синтетические оценки удовлетворённости — с числом ответивших и пропусками.
- **Отчёт одним файлом:** интерактивный HTML без внешних ресурсов, а также Markdown и JSON. Тёплый фон, карминные акценты, крупные числа и лёгкая анимация при прокрутке.

## Посмотреть пример без ключа

В корне репозитория:

```bash
python examples/generate_demo.py
```

Откройте `examples/report.html`. Команда строит демонстрационный отчёт: она не тестирует сайт и не тратит деньги на модели.

## Запустить тест

Нужен Python 3.10+ на macOS или Linux; на Windows — WSL.

**Основной вариант — через скилл.** Установите всю папку [`skills/audience/`](../skills/audience/) в совместимого ассистента и напишите запрос. Так можно использовать его браузер и уже авторизованный тестовый аккаунт. [Инструкция и требования](installation.md).

**Самостоятельный запуск через Playwright пока экспериментальный:**

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[browser]'
python -m playwright install chromium

audience run https://your-product.example \
  --task "Проверь, понятно ли, как найти товар и узнать цену. Остановись до покупки." \
  --budget 2 \
  --max-minutes 30 \
  --output runs/first-study \
  --prompt-key
```

Замените пример URL своим сайтом. Ключ OpenRouter вводится скрыто через `--prompt-key`; другой вариант — переменная `OPENROUTER_API_KEY` из менеджера секретов. Не вставляйте ключ в команды, файлы проекта или публичные обсуждения.

Автономный браузер создаёт отдельные контексты и прежде всего подходит для навигации по публичному сайту. Его защитные ограничения могут блокировать POST-запросы; авторизация и отправка сообщений в чат не входят в поддерживаемый быстрый запуск. Для авторизованного аккаунта или AI-чат-продукта используйте браузер ассистента через режим `host`.

## Несколько агентов и разные модели

По умолчанию Audience читает актуальный каталог OpenRouter, выбирает совместимые текстовые модели и небольшую группу агентов в рамках бюджета. Выбор основан на доступности, цене и возможностях моделей; это не доказанно оптимальная комбинация.

```bash
audience models --eligible --limit 20

audience run https://your-product.example \
  --task "Сравни первое использование и повторный визит. Без оформления заказа." \
  --agents 12 \
  --models provider/model-a,provider/model-b \
  --scenarios first_use,resume,regular \
  --concurrency 3 \
  --budget 5 \
  --max-minutes 30 \
  --output runs/manual-study \
  --prompt-key
```

Укажите настоящие ID моделей из каталога. Можно запросить **от 1 до 1 000 персон**; сколько завершит тест, зависит от бюджета, времени и продукта. Запланированные, но не запущенные агенты не попадут в число протестировавших.

**Если браузер один**, режим `host --session-mode shared_account` запускает персон по очереди. У каждой — отдельная история модели и отдельный чат в продукте. Память продукта, лимиты и персонализация аккаунта могут быть общими — отчёт это указывает. Автономный режим поддерживает от 1 до 8 одновременных контекстов. [Подробнее о режимах](../skills/audience/references/runtime.md).

## Где запросы и ответы

В меню отчёта есть «Диалоги», на первом экране — «Запросы и ответы». Для чат-продуктов ассистент должен сохранить фактически отправленные сообщения и видимые ответы. Audience не восстанавливает переписку по впечатлениям агента. Если сообщения не сохранены, отчёт явно это показывает и оставляет доступ к наблюдениям браузера.

Универсальный адаптер Playwright пока записывает наблюдения, но не определяет автоматически роли сообщений во всех чат-продуктах.

Пересобрать отчёт из уже записанного теста можно бесплатно, без новых вызовов моделей:

```bash
audience report runs/first-study/run.json --output reports/first-study
```

## Как понимать цифры

AI-персоны помогают находить проблемы и формулировать гипотезы. Это не выборка реальных клиентов. Даже довольный агент может пропустить ошибку в ответе, поэтому его впечатление отделяется от проверки результата.

Оценки CSAT/NPS и желание вернуться обозначены как синтетические. **Они не доказывают реальный retention, CAC, DAU или MAU.** Прогнозы этих метрик считаются только из явно заданных внешних данных и допущений через `--forecast-inputs`. Сжатая симуляция повторного визита не заменяет наблюдение через 7 или 30 дней.

Текущий исполнитель использует текст и DOM, а не визуальную оценку дизайна. Интерфейс отчёта — на русском. Полный запуск в Claude пока не проверен; [статус проверки и ограничения](../skills/audience/references/validation.md) описывают фактически испытанные варианты.

## Бюджет и данные

Лимит OpenRouter общий для проверки моделей, планирования, действий агентов и итогового анализа. Перед вызовом резервируется его оценочная стоимость. Неопределённые списания остаются в резерве; подтверждённые расходы показаны отдельно. Подписка на ассистента, браузерная инфраструктура и расходы в тестируемом продукте в этот лимит не входят.

Видимый текст продукта передаётся OpenRouter и выбранным провайдерам моделей. Используйте разрешённые тестовые аккаунты и подходящие данные. Папки запусков, переписки и скриншоты не публикуйте без отдельной проверки. В примерах этого репозитория только вымышленные данные.

Основной сценарий останавливается перед оплатой, бронированием, сообщением другим людям, разрушительными действиями и неожиданными ограничениями доступа. Защитные проверки браузера не превращают произвольный рабочий аккаунт в безопасную тестовую среду.

## Разработка

```bash
python -m unittest discover -s skills/audience/scripts/tests -v
```

Код находится в `skills/audience/scripts/`. CI использует офлайн-примеры и заглушки: прохождение проверок кода не означает, что был протестирован живой продукт.

Можно помочь с браузерными адаптерами, сохранением переписок, переводом отчёта и сравнением результатов с исследованиями реальных пользователей.
